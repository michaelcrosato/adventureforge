Critical learnings and codebase-specific performance patterns for AdventureForge.

## 2026-09-22 - Maintainer note — how to land a Bolt change here
**Learning:** Sixteen Bolt PRs (#372–#388) sat unmerged, most redoing each other: four rewrote `canonicalize` (#376/#378/#379/#387), three `stateKey` (#374/#381/#382), two the blocked-action pass (#377/#384), two USE presence gating (#380/#385). Several changed behavior: a `value.constructor === Object` fast path lets a Map carrying an own `constructor` key past the bug_0607 guard, #384 dropped blocked hints, #385 changed what is legal. The sound ideas were consolidated in one maintainer change, each proven byte-identical first; the biggest `canonicalize` win (V8 dictionary-mode `Object.create(null)` accumulators) was in none of them.
**Action:** Before starting, read the open Bolt PRs and this journal, and never re-attempt a hot spot that already has an open PR. One change per PR. `src/core`, `src/rpg`, `src/solve` (the full list is `CENSUS_PROOF_SOURCE_SCOPES` in `scripts/test-lanes.ts`) are census-proof scope: run the FULL `npm run health` — typecheck and lint alone are not the bar — and never change canonical output bytes, key order, action ordering or state hashes. Measure with `npx tsx scripts/bench-engine-hot-paths.ts` (its checksums must not move); commit any benchmark script you measured with and report reproducible before/after medians. Date entries with the real current date — the entry below says 2025 but was written in 2026.

## 2026-09-23 - Fast-path reference equality in makeStep action legality checking
**Learning:** In solver BFS searches and step execution loops, `step(state, action)` tests if `action` is in `rules.legalActions(state)`. The legal actions returned by resolvers are the exact action object references passed into `step`. Checking reference equality (`legalActions.includes(action)`) before fallback `canonicalize()` JSON stringification avoids thousands of stringify allocations on legal transitions, speeding up `search tide_mill` by ~10% (from 10,508 ms down to 9,514 ms) while maintaining identical checksums.
**Action:** When validating object membership in a collection where elements are generated by the caller, always attempt reference equality (`includes` / `Set.has`) before falling back to canonical serialization / structural comparison.

## 2025-05-18 - WeakMap caching of worldHash for frozen OverworldManifest
**Learning:** `hashState(world)` takes ~100ms on the large overworld manifest object because canonical serialization recursively sorts keys and formats JSON. When building `OverworldSessionIndexes`, this calculation was being re-run on every session initialization. Caching the result via a module-level `WeakMap` for `Object.isFrozen(world)` instances eliminates this ~100ms overhead for subsequent sessions with zero risk of stale data or memory leaks.
**Action:** Always check if heavy serialization or hashing functions are repeatedly invoked on immutable/frozen domain objects, and use a `WeakMap` cached by object identity.
